# Working with Glow

Read `README.md` and `docs/install.md` for installation requests. Version 0.10.6 provides explicit `--local-signing` with a persistent identity generated on the user’s Mac; no Apple-issued certificate or membership is required. It remains experimental. Read docs/verification.md for the actual scope of testing. A browser-only chat cannot build on the user’s Mac.

- Preserve existing source edits and `.local/` originals, staging, reports, and recovery data. Never commit or upload that directory, app bundles, account data, or signing material.
- For installation requested inside Codex/ChatGPT, run Refresh with `--prepare-only` and the chosen signing mode. In no-certificate mode use `"./Refresh Neon Codex.command" --local-signing --prepare-only`. Verify the build and installation preflight, then give the exact absolute command with the same mode for a separate persistent Terminal window. Do not start the waiting installer from the app-hosted session or quit the host app.
- Explain local signing accurately: Glow automatically creates a private self-signed identity, not an Apple-issued certificate. It pins code requirements to that certificate and each code identifier and reuses the identity across refreshes. It adds an app-scoped library-validation exception and is not notarized. Keep this an explicit choice, never a silent fallback. Preserve hardened-runtime flags, Electron fuses, CSP, quarantine, and system protections. Do not disable SIP or Gatekeeper. Do not claim all protections are unchanged; library validation changes for this app.
- Preserve `~/Library/Application Support/Glow/Signing` across updates and re-clones. Never upload its files, rotate a missing/mismatched identity silently, use an identifier-only designated requirement, or edit existing Keychain item access to suppress authorization. Initial migration can require user approval; do not promise prompts can never recur. Test Keychain access only with isolated disposable data unless the user explicitly authorizes a different action.
- Apple certificate mode remains available. If several valid identities exist, ask which to use; never invent or export a private key. Do not combine `--identity` with `--local-signing`.
- For an unreviewed app update, read `docs/compatibility.md` and run `scripts/compatibility.mjs` against the actual OpenAI-signed source, or the matching preserved original if the app is patched. Unknown versions can produce a structural candidate. Review the real Appearance mount, settings bridge, renderer, and builder transformation before any compatibility change; a candidate is not automatic approval. Never make an app pass by changing only a version, hash, or signature assertion. A local assistant can perform this review without waiting for a publisher signature, but may need to adapt changed integration code.
- For source changes, run appropriate checks. Keep preview behavior aligned with the app patch. Native testing is separate; never report it passed from fixture, syntax, signature, or packaging checks. Do not launch or quit the host app as part of preparation.
- Keep changes focused. The public repository contains source and documentation, never a redistributed OpenAI application. Do not describe uncommitted candidate work as published or universally supported.

- The existing titlebar Toggle Sidebar command may cycle through native chat-list hiding, expanded chats with the icon rail hidden, and the normal layout. Do not add a duplicate sidebar toggle. Keep the real account control accessible and provide Settings Home only while the rail is hidden. Any native bridge must be optional, fail open to native behavior, and must not import Glow into the initial renderer's dependency graph. Pin and test the exact reviewed integration.
- Native startup initially has no window-type attribute. Retain early-window and isolated native bootstrap checks; Glow must remain separate from native entry-module dependencies. Theme transitions must preserve native layout/resize/opacity transitions and avoid rescanning conversations during streaming. Native application testing remains separate from isolated module execution.
